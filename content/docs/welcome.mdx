**Dashforge** (by Finbox) lets you build the screens your team uses to work a
loan, without writing any code. A **dashboard** controls what a user sees
(fields, documents, data) and what they can do (buttons, actions), and this can
differ by role, an Underwriter reviewing an application needs a very different
screen from a Disbursal Officer tracking payouts. Instead of asking engineering
to build each of those screens, you design and update them yourself in
Dashforge.

Throughout this guide we build one example together, a **Test Dashboard for ABC
EL (Aditya Birla Capital - Education Loans)**, so each step builds on the last
instead of jumping between unrelated examples.

## The screen you land on after login

If your account has used Dashforge before, you go straight to the **Dashboards
list**, a table of every dashboard already created for your organization. (A
brand-new account first sees a short intro screen with a **"Build Dashboard
Now"** button that leads to the same place.)

Each row is one dashboard, showing:

- **Name**: the dashboard's name.
- **Status**: either `Draft` (still being built, not live) or `Published`
  (live for real users).
- **Updated at / Updated by**: when it was last changed and by whom, so you can
  tell what's recent and who's working on it.
- **Actions**: the menu (⋮) for that dashboard: Edit, Publish, Clone, etc.

Above the table, two dropdowns narrow the list down: **Dashboard Type** (e.g.
*Lender Dashboard*) and **Client** (e.g. *Zype*, *ABC EL*), useful when there
are many dashboards and you only want one client's.
